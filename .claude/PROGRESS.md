### 메모 — 데이터셋 (TORGO)
- 출처: Rudzicz et al. 2012 (Univ. of Toronto). Kaggle 재업로드본 2,000 샘플.
- 구성: 구음장애 8명 / matched control 7명 = **15명**. 클래스 1000:1000, 성별 500:500.
- 라이선스: **academic only, 재배포 금지** → `torgo_data/`, `data.csv` gitignore 대상.
- ⚠️ 한계(포트폴리오에 명시할 것): **영어** 발화, 병인이 **뇌성마비·ALS**(뇌졸중 아님).
  한국어 후보(AI Hub 71434)는 **안심존 전용**이라 반입·반출 불확실 → 파이프라인 완주 가능성을 우선해 TORGO 선택.
- AI Hub 신청은 결과를 기다리지 않는다. 승인되면 "한국어 검증 확장" 카드로만 사용.

### 메모 — 8단계 baseline 비교 (2026-10-13)
- 동일 조건: 1,991개 / 화자 단위 5-fold / seed 42 / OOF 풀링. `speechml/baseline_rf.py`, `speechml/compare.py`
- **ROC-AUC: wav2vec2 0.818 vs 옛 레시피 RF 0.562** (0.5가 무작위)
- thr=0.5 → w2v Acc 0.757 / RF 0.569. thr=0.15 → w2v Acc 0.726 / RF **0.429**
- ⚠️ **RF의 "Recall 0.800"은 허수**: 정상 1,000명 중 **938명을 구음장애로 오탐**(FP 938).
  사실상 "전부 양성"이라고 답하는 분류기. 화자별로 보면 정상군 정확도가 FC02 0.026 / FC03 0.017 / MC01 0.023 / MC03 0.026 / MC04 0.010.
- threshold 스윕(0.70~0.15)에서 RF는 **어느 지점에서도 w2v를 못 이긴다**. RF 최고 Acc는 thr=0.60의 0.608(Recall 0.469).
- 🚨 **비교의 한계 — DTW는 "고정 프롬프트"를 가정한다**:
  원 서비스는 `front-end/src/components/SpeechTestPage.jsx:6`의 **고정 자기소개 문장**을 읽게 하고,
  `dtw_refs.pkl`은 **그 같은 문장**의 정상 화자 녹음이었다. `target_duration_s=10.0` + 5분할도 이 설계의 산물.
  TORGO는 **서로 다른 단어/구**라 참조와 내용이 애초에 다르다 → 10 feature 중 6개(DTW 5 + slope)가 사실상 노이즈.
  즉 AUC 0.562는 "레시피가 약하다"와 "데이터-레시피 불일치"가 섞인 값이다. **과대 주장 금지.**
- ✅ 그래서 정직한 결론은 둘:
  (1) 옛 레시피는 **이 데이터셋에서 판별력이 거의 없다** (AUC 0.562).
  (2) 그 원인의 상당 부분이 **레시피가 데이터 수집 프로토콜에 강하게 결합돼 있기 때문**이다.
      고정 프롬프트 + 프롬프트별 참조가 있어야만 작동한다. 새 모델은 그 전제가 없다 — 이게 실질적 개선점.
- 미검증: 참조를 "같은 프롬프트"로 제한하면 RF가 나아지는지. Kaggle 재업로드본에 전사 텍스트가 없어 확인 불가
  (발화번호가 화자 간 겹치지만 프롬프트 정렬 보장 없음). 원본 TORGO 전사 파일이 있으면 검증 가능.

### 메모 — 6·7단계 결과 (2026-10-10)
- **확정 설정**: `wav2vec2-base` freeze → layer **8** → **mean** 풀링(768차원) → StandardScaler + LogisticRegression(C=1.0)
- **확정 threshold: 0.15** (기본 0.5 아님). `config.DECISION_THRESHOLD`
- **성능 (OOF 풀링, n=1991, thr=0.15)**: **Recall 0.777** | Precision 0.703 | F1 0.738 | Acc 0.726 | **AUC 0.818** | **FN 221** | FP 325
  - fold별 Recall 0.871 ± 0.186
  - thr=0.5 기준: Recall 0.727 | Precision 0.773 | F1 0.749 | Acc 0.757 | FN 271 | FP 212
  - 6단계 기준선(layer 12 + mean, thr=0.5): Recall 0.641 | AUC 0.710 | FN 356
- threshold 0.15의 효과는 **균일한 이동이 아니라 경증 쪽에 집중**됐다 (의도한 방향):
  F03 0.226→0.401 / F04 0.789→0.850 / M03 0.720→0.810.
  대가는 정상군 오탐: FC03 0.545→0.333 / MC04 0.500→0.292 / FC01 0.795→0.667.
- **기각된 가설 1 — 과적합**: C를 0.0001까지 낮추고 PCA 32~256을 써도 단조롭게 나빠졌다. 정규화 문제가 아니었다.
- **기각된 가설 2 — 하이퍼파라미터 튜닝**: 중첩 CV에서 fold별 선택 C가 0.0001~1로 불안정, 결과도 고정값보다 나빴다(AUC 0.619 vs 0.710). → **C=1.0 고정**. 선택 과정이 없으므로 수치에 selection bias가 없다.
- **검증된 가설 — 표현**: 39조합 스윕에서 AUC가 역U자. layer 0=0.63 → **layer 8=0.82** → layer 12=0.71.
  마지막 레이어는 사전학습 과제에 특화돼 병리 신호가 깎인다(레이어 11·12에서 시간축 std가 0.19→0.12로 급락).
- **std 풀링은 기대와 달리 최적 레이어에서 무효**. 하위 레이어(1~5)에서만 mean보다 좋았다. EDA의 "분산이 신호" 직관은 부분적으로만 맞았다 — 과대 서술하지 말 것.
- ⚠️ **남은 한계 — 경증을 못 잡는다**: 화자별 OOF 정확도가 중증 쪽은 거의 완벽(M01 1.00, M02 1.00, M04 0.99, M05 0.98, F01 0.99)인데 **F03(n=292)은 0.23**.
  F03 확률 중앙값은 layer12 0.002 → layer8 0.037로 올랐지만 여전히 반대편 극단. threshold로 구제 불가.
  → 표현 개선은 정상군 오탐을 크게 고쳤으나(FC03 0.898→0.450) 경증 탐지는 **데이터 수준의 한계**로 보인다. 경증 화자가 train에 2~3명뿐.
  TORGO 원 논문의 화자별 명료도 점수와 대조해 "중증도 기울기"를 수치로 입증할 것.
- 오탐 잔존: MC04(정상) 확률 중앙값 0.725.

### 메모 — EDA 결론 (2026-10-10)
- **유효 샘플 1,999개** — `F01_Session1_0068.wav`가 0바이트라 로드 실패 1건. 클래스 999:1000.
- **샘플레이트 전부 16kHz 단일** → 리샘플링 불필요. wav2vec2 입력 요건과 일치.
- **발화 길이는 라벨을 누출하지 않는다** (shortcut 위험 낮음):
  - 발화 단위로는 구음장애가 평균 32% 길어 보이지만(3.56s vs 2.69s),
  - **화자별 중앙값 15개로 보면 완전히 섞인다** (최단 F01=1.73s 구음장애, 최장 FC01=3.30s 정상). 평균 차 9%.
  - → 집계 단위를 바꾸면 결론이 뒤집힌다. 화자 단위 결론을 채택.
- **진짜 신호는 평균이 아니라 분산**: std 2.88(구음장애) vs 1.30(정상), max 25.3s vs 12.7s.
  → "화자 내 길이 변동성"은 feature 후보. 6단계에서 재검토.
- **필터 기준: `duration_sec >= 0.3`** (8개 제거, 전부 M05, 8ms~43ms 녹음 사고).
  근거: 0.3s=4,800샘플로 MFCC 프레임(2,048) 2개 확보. 0.5s 이상으로 올리면 "짧은 발화"라는 실제 증상을 지움.
- 미확인 항목(필요해지면 돌아올 것): 노이즈/RMS 분포, 세션별 녹음 레벨, **중복 파일 검사**(M05에 동일 길이 파일 2~3개).
- `parse_filename`이 `Session2_3` 65건을 `Session2`로 흡수 중. 화자 단위 split에는 영향 없음.
